# HOPE VPN

Telegram-бот, независимый браузерный кабинет и управление существующими подписками 3x-ui. Реализовано без BMAD. Деньги переводят владельцу, коммерческое продление подтверждает только он; платёжной автоматизации нет.

Новый клиент может выбрать срок и оформить заказ прямо в Telegram; после ручной выдачи он сам задаёт логин/пароль кабинета по одноразовой ссылке. Существующие пользователи получают аккаунт по проверенному приглашению. Для существующего браузерного аккаунта Telegram необязателен и подключается после подтверждения в боте и исходном браузере. Существующие VPN-ссылки сохраняются.

## Локальный запуск

Кабинет: [http://127.0.0.1:8000](http://127.0.0.1:8000). Управление: [http://127.0.0.1:8000/staff/](http://127.0.0.1:8000/staff/).

`.env` создан с правами 0600 и исключён из Git. Учётные данные владельца — `LOCAL_ADMIN_LOGIN` / `LOCAL_ADMIN_PASSWORD`. При первом входе отсканируйте QR в Google Authenticator или другом TOTP-приложении и введите показанные им 6 цифр. Если кабинет открыт на том же телефоне, раскройте ручной ключ и добавьте его в приложение как ключ по времени. Секрет нужно сохранить отдельно для восстановления.

```sh
docker compose --profile telegram up -d --build web worker bot
docker compose exec web python manage.py bootstrap_owner
```

Настроен реальный бот @hope2vpnbot. Для локального подключения к действующей панели используется отдельная база приложения `hope_live`; панельная БД не меняется. Старые демонстрационные данные сохранены в базе `hope`.

**Панель находится в production. Запись выключена: `PANEL_WRITES_ENABLED=false`.** Импорт и привязка Telegram работают без записи в 3x-ui. Включать панельные изменения следует после бэкапа, проверки отдельного тестового клиента и оценки риска node-sync.

После изменения `.env` пересоздайте сервисы, чтобы обновить их окружение:

```sh
docker compose --profile telegram up -d --force-recreate web worker bot
```

`127.0.0.1` доступен только на этом компьютере. Для использования кабинета с телефона понадобится адрес, доступный ему, и соответствующие hosts/origins; приложение не публикуется через туннель автоматически.

Публичный адрес согласован: домен панели, путь `/hope/`. Поддержка префикса и [пример Nginx](deploy/nginx-hope-location.conf) подготовлены; удалённое развёртывание не выполнялось. Настройки — в [инструкции](docs/operations.md#кабинет-на-домене-панели-hope).

## Что реализовано

- Полный Telegram-сценарий: тариф → выбранный срок/цена → заказ → «Я оплатил» → ручная проверка → ручная выдача → подтверждение готовности → устройство/приложение.
- Административные [заказы](http://127.0.0.1:8000/staff/orders/) и поддержка в боте, включая новых клиентов без аккаунта. Реквизиты владелец присылает лично.
- INCY для iPhone/iPad, Happ как альтернативный клиент, копирование персональной ссылки и импорт из кабинета.
- Экстренный час в кабинете после истечения: раз в 3 часа, максимум 8 запросов за сутки по МСК; требуется разрешённая запись в панель.
- Приглашения и регистрация; восемь одноразовых кодов восстановления; безопасная отвязка Telegram и восстановление владельцем.
- Кабинет, персональная ссылка/QR, импорт в Happ, инструкции и обращения с ответами.
- Заявка на существующую подписку одним нажатием; события в админскую Telegram-группу через outbox.
- Административный вход с TOTP, комментарии панели в таблице/карточке и поиске, read-only импорт, исключение служебных записей и принятие подписок под управление.
- Создание доступа, календарное/дневное продление, точная дата и блокировка — с предпросмотром и защитой от повторного применения.
- Адаптер API 3x-ui, сохранение секретов/квот/привязок, проверка каждого инбаунда и состояния core/нод.
- Очередь PostgreSQL, сверка после таймаутов, состояния partial/conflict и остановка записей при неоднозначном результате.
- Напоминания, сообщения о продлении, админские уведомления об ошибках и массовые сообщения с предпросмотром получателей.
- Шифрованные снимки/бэкапы и восстановление с обязательной сверкой перед продолжением записи.

## Разработка и проверки

```sh
uv sync
uv run pytest -q
uv run ruff check .
uv run python manage.py check
```

Native-режим без `DATABASE_URL` использует локальную SQLite; Docker — отдельный PostgreSQL на localhost:15432. Это разные базы. Проверка конкурентных блокировок требует PostgreSQL. `scripts/init_env.py` создаёт новую `.env` только при её отсутствии, не перезаписывая секреты.

Для чистой демонстрации используйте отдельную БД, `PANEL_MODE=demo`, `bootstrap_local` и отключённый токен/worker во время browser smoke. Полная инструкция — ниже.
