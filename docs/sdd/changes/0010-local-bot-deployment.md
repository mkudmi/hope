# 0010 — Локальный запуск Telegram-бота через Docker

Статус: verified (локальный запуск сервисов). Создано: 2026-10-12. Обновлено: 2026-10-12.
Связанные требования: R-01, R-08, R-12, R-15. Решения: не требуются.

## Проблема и результат

Пользователь разрешил запуск на текущем компьютере через Docker. Снимок прежнего
окружения не совпадает с текущим: Docker Engine первоначально недоступен, в `.env`
отсутствуют ключи приложения и пароль БД, выбран demo, имя бота не соответствует
токену. Telegram getMe подтвердил @hope2vpnbot; webhook отсутствует.

## Объём и требования

- Запустить локальные сервисы с long polling, не публикуя кабинет.
- До изменения ключей и пароля БД проверить существующие контейнеры и volumes;
  имеющиеся ключи и данные сохранять. Секреты не печатать.
- Исправить BOT_USERNAME по getMe. Сохранить PANEL_WRITES_ENABLED=false и localhost.
- Не создавать demo-клиентов и не импортировать панель ради проверки запуска.
- Не отправлять искусственные Telegram-сообщения. Проверку ответа в личном чате
  выполняет владелец настоящей командой /start.
- Если параметры реальной панели отсутствуют, не объявлять запуск интеграцией
  действующей панели; явно указать ограничение.

## Критерии приёмки

- AC-01: целевая локальная БД известна; существующие данные/ключи не заменены.
- AC-02: web здоров, штатные миграции применены, Django check успешен.
- AC-03: bot работает без перезапусков и конфликтов polling; имя и отсутствие
  webhook подтверждены Telegram API.
- AC-04: запись панели выключена; кабинет остаётся на localhost; результаты и
  ограничения отражены в документации.

## Решение и влияние

Использовать существующие compose.yaml и runbot. Исправления локальной `.env`
не входят в Git. Запуск Docker Desktop разрешён как часть локального развёртывания.
Откат: остановить bot/worker/web без удаления БД и volumes. Изменения сервера
панели и публичного прокси вне объёма.

## Итог и ограничения

Docker Desktop запущен, образы собраны из requirements.txt. Созданы недостающие
ключи и пароль БД/владельца для чистого окружения; токены Telegram и панели
сохранены. Исправлен BOT_USERNAME, установлен real/write-off,
APP_DATABASE_NAME=hope_live, утверждённые тарифы включены. База hope_live создана
штатным createdb до миграций web. Владелец создан через bootstrap_owner;
пароль хранится только в .env, первый вход требует настройки TOTP.

Реальный туннель, чтение панели, доставка в группу и ответ на /start не проверены.
Пустая база не содержит прежних подписок. PANEL_SUB_URL не заполнен; интеграцию
выдачи подписок нельзя считать настроенной. Создание/продление VPN запрещено
write-off. Кабинет доступен только на этом компьютере, /hope/ публично не развёрнут.
Автотесты и browser smoke не запускались: код приложения не менялся.
