# 0007 — Заявка на привязку и события в админскую группу

Статус: verified. Дата: 2026-10-12. Требования R-03/R-08/R-15.

Кнопка «Существующая подписка»/«У меня уже есть подписка» в личном чате сразу создаёт административное обращение binding и уведомление в Telegram администратора через outbox. Передаются username (если есть), имя, фамилия (если есть), Telegram ID и ссылка на контакт; это не подтверждение владения подпиской. Пользователь получает состояние ожидания и кнопку повторной проверки, без ввода сообщения.

Критерии: одна открытая binding-заявка на контакт, включая конкурентные нажатия; уже привязанный активный аккаунт не создаёт заявку; отсутствие username/фамилии допустимо; групповой чат ничего не создаёт. Повторный запрос показывает ожидание без повторной рассылки. Администратор отвечает через «Обращения», ответ приходит пользователю, закрывая обращение; привязка остаётся через проверку прежнего контакта/приглашение/подтверждение в кабинете. Панель не меняется, автоматического выбора записи по имени нет. Если администратор закрыл вопрос без привязки, допускается новая заявка.

Реализация: существующие Request/BotContact/Notice, блокировка строки контакта, транзакционная заявка+outbox; отдельные миграции не нужны. Тесты только с имитацией Telegram API, реальные сообщения для проверки не отправлять.

Дополнение владельца: события должны приходить в существующую админскую группу, ID уже в .env. ADMIN_GROUP_CHAT_ID приоритетен, если отсутствует — ADMIN_CHAT_ID (может быть отрицательным ID группы). Отдельная маркировка admin_event в outbox исключает перенаправление персональных уведомлений/секретов в группу. Групповые события: заявки/поддержка, новые/отменённые заказы, заявление о переводе, ручное решение, очередь/результат/ошибка операций, Telegram-привязка. Никаких приглашений, recovery/onboard ссылок, паролей, VPN-ссылок или текста банковских реквизитов; используются идентификаторы и ссылки в защищённую админку. 403/429/retry действуют как у существующего outbox. Реальный тестовый event не отправлять.
