# 0001 — Правила агентов и внедрение SDD

Статус: verified. Создано: 2026-10-12. Обновлено: 2026-10-12.
Связанные требования: R-12. Отдельный ADR не требуется: процесс прямо задан пользователем.

## Проблема и результат

У проекта есть реализация и подробные документы, но не было корневых правил для агентов и обязательного процесса актуализации спецификации. Пользователь запросил AGENTS.md и регулярную документацию в SDD-формате.

## Объём

Создать правила, карту кода, текущую базовую SPEC, индекс изменений и повторно используемый шаблон. Сохранить ранее заданные ограничения: без BMAD, ручные коммерческие продления, действующая панель только чтением. Приложение и окружение не менять; автоматизации по расписанию не создавать.

## Критерии и проверки

| Критерий | Документ | Проверка | Результат |
|---|---|---|---|
| AC-01: агенты видят контекст, команды и ограничения действующей панели | `AGENTS.md` | Сверка с картой кода, compose и документацией текущего запуска | выполнено |
| AC-02: задан обязательный процесс до/во время/после содержательного изменения | `AGENTS.md`, `docs/sdd/README.md` | Чтение правил: спецификация, критерии, решения, результаты и обновление документов | выполнено |
| AC-03: базовые требования имеют стабильные ID и связи с реализацией/проверками | `docs/sdd/SPEC.md` | Сверка путей и отчёта базовой реализации | выполнено |
| AC-04: есть шаблон и индекс, ссылки разрешаются, секреты не включены | `docs/sdd/`, `README.md` | Автоматическая проверка локальных ссылок/путей; просмотр новых документов | выполнено |

## Итог и ограничения

Процесс принят для следующих задач и применяется в текущей. Менялось только документирование; тесты приложения не запускались, так как поведение не изменилось. Прежний отчёт реализации остаётся историческим доказательством, а не новым запуском тестов. Регулярность обеспечивается правилом каждого изменения, без фонового расписания.
