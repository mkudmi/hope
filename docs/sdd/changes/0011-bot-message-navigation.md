# 0011 — Навигация бота в одном сообщении

Статус: verified (автотесты; ручной Telegram-сценарий отдельно). Создано: 2026-10-12. Обновлено: 2026-10-12.
Связанные требования: R-03, R-09, R-15, R-16. Решения: не требуются.

## Проблема и результат

Каждый callback отправляет новое сообщение и засоряет историю чата. Пользователь
просит менять текущий экран при нажатии кнопок. Текст и inline-клавиатура
обновляются в сообщении, кнопку которого нажали.

## Объём и требования

- Все callback-экраны, включая заказы, помощь, привязку, ошибки, устройства и
  кабинет, используют editMessageText; команды и ответы на текст остаются новыми
  сообщениями. Уведомления outbox остаются отдельными сообщениями.
- Повтор неизменного экрана (message is not modified) не создаёт дубль.
- Только при явном отказе «message to edit not found» / «message can't be edited»
  отправить замену. Сетевые ошибки, 429 и прочие ошибки не вызывают слепую отправку.
- Недоступное сообщение callback и групповой чат не получают секреты.
- Права, бизнес-правила, заявки, ручная оплата и write-off не меняются.
- Экран кабинета получает кнопку возврата. Старые сообщения не удаляются.

## Критерии приёмки

- AC-01: цепочка меню → цены → тариф → назад обновляет один message_id без sendMessage.
- AC-02: оформление/проверка/отмена заказа, поддержка и привязка используют тот же
  экран; сохранение данных и проверка владельца остаются прежними.
- AC-03: неизменный экран не дублируется; явная невозможность редактирования даёт
  одно новое сообщение, прочие ошибки не дают запасного sendMessage.
- AC-04: команды и отдельные уведомления сохраняют прежнюю доставку; групповые
  и недоступные callback не раскрывают данные.

## Решение и влияние

Общий render_screen в core/bot.py выбирает answer для команд и edit_text для
callback. Документы UC-B001–UC-B047 уточняют общую механику; URL/copy_text-кнопки
не вызывают редактирование. Миграции и новые настройки не нужны. Откат — возврат
core/bot.py и пересборка только bot. Запись действующей панели не включается.

Контракт: [Telegram editMessageText](https://core.telegram.org/bots/api#editmessagetext).
Проверки только с FakeSession и отдельной тестовой БД, без реальных сообщений.

## Итог и ограничения

Реальная навигация Telegram проверяется владельцем после обновления локального
bot. История прежних сообщений сохраняется; глобальное единственное сообщение
между разными /start не вводится.

UC callback-кнопок, их индекс/INVENTORY, SPEC, README, product, architecture и
operations обновлены. Модели, миграции, outbox и панельные операции не менялись.
В тестах не было реальных сообщений. В первом прогоне выявлена неоднозначность
десериализации date=0 в aiogram; исправлена явной проверкой нулевой даты.
Результаты исследования и обновления контейнера — в [отчёте](../../research/2026-10-12.md).
Пересобран и пересоздан только bot (--no-deps), runtime Python 3.12.15.
Новый код присутствует, bot running, 0 перезапусков, маркеров ошибок нет.
PANEL_WRITES_ENABLED=false подтверждён внутри контейнера.
