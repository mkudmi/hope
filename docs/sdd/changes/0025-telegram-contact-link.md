# 0025 — Рабочая ссылка на Telegram-профиль в binding-заявке

Статус: verified (payload и регрессия изолированно; Telegram клиент/выкладка не проверены). Создано: 2026-10-13. Обновлено: 2026-10-13.
Связанные требования: R-03, R-08. Решения: не требуются.

## Проблема и результат

Уведомление содержит голый `tg://user?id=…`, который Telegram не делает рабочим
упоминанием. По официальному Bot API такая ссылка работает внутри inline link
или inline keyboard, а доступность дополнительно зависит от приватности.
Источник: [Telegram Bot API / Formatting options](https://core.telegram.org/bots/api#formatting-options).

## Объём и требования

- Контакт в новом уведомлении — кликабельный текст «Открыть профиль».
- При username ссылка ведёт на `https://t.me/<username>`, без username — на
  `tg://user?id=<telegram_id>` через явную `text_link` entity.
- В outbox сохраняются entity и исходный текст. Доставка отправляет entities
  только при наличии, без HTML/Markdown parse_mode. Профильные имена остаются
  обычным текстом и не могут внедрить форматирование.
- Offset/length рассчитываются в UTF-16 по контракту Telegram, включая emoji.
- В тексте браузерной заявки при username сохраняется HTTPS контакт; без него
  указывается ответ через обращение. Приватность может ограничивать ID-ссылку;
  ответ через кабинет/бот остаётся запасным каналом.
- Идемпотентность заявки и доставки, группа/fallback, ручная проверка владения
  и персональная доставка ответа сохраняются.
- Старые отправленные сообщения не редактируются. Не выкатывать на стенд;
  проверки изолированы, Telegram API имитируется, панель не вызывается.

## Критерии приёмки

- AC-01: заявка с username создаёт правильную `text_link` на HTTPS профиль.
- AC-02: заявка без username создаёт `text_link` на Telegram ID; raw URI
  отсутствует в текстовом теле уведомления/заявки.
- AC-03: emoji и символы HTML/Markdown в имени не портят границы ссылки и
  остаются обычным текстом; payload не включает parse_mode.
- AC-04: worker передаёт entity и правильный адресат группы; уведомления без
  entities продолжают отправляться без поля entities.
- AC-05: повторный запрос не создаёт новую заявку/уведомление, entity сохраняется
  после ошибки/повторной доставки.

## Решение и влияние

`Notice.telegram_entities` — JSON-массив с default=list; миграция 0008 зависит
от подготовленной 0007. Сервис admin_event/admin_notice принимает entities.
Binding-заявка формирует контакт отдельной entity; worker передаёт её как часть
sendMessage. Изменения не требуют новых настроек и не обращаются к панели.
Откат кода допустим до выкладки; миграцию применять штатно при будущей выкладке.

## Итог и ограничения

Ссылка по ID не обходит приватность Telegram и не доказывает владение подпиской.
Проверка открытия профиля в реальном Telegram клиенте пока не выполнена.

Первый прогон на SQLite в памяти дал ошибки отсутствия таблиц в асинхронных
потоках (5 failed, 37 passed, 1 skipped). После замены тестового окружения на
отдельную временную SQLite все выбранные сценарии прошли. Продуктовые базы,
службы, панель и реальные Telegram сообщения не затрагивались. Не развёрнуто.
