# 0020 — Открывать привязку в Telegram приложении

Статус: verified (CI + Czech production deploy; device handoff pending). Создано: 2026-10-13. Обновлено: 2026-10-13.
Связанные требования: R-23. Решения: не требуются.

## Проблема и результат

В production браузерная кнопка HTTPS `t.me` не передаёт диплинк в Telegram приложение на устройстве пользователя. На странице привязки нужен прямой `tg://` переход с тем же одноразовым start-токеном и HTTPS запасной вариант.

## Объём и требования

- Сформировать `tg://resolve?domain=<bot>&start=<token>` из текущего одноразового токена и настроенного BOT_USERNAME.
- Главная кнопка запускает приложение через `tg://`; рядом оставить HTTPS `t.me` fallback.
- Оба перехода используют один и тот же токен, не продлевают его и не завершают привязку автоматически.
- Сохранить текущие шаги: нажать Start в боте, подтвердить, вернуться в исходный браузер и завершить привязку.

## Критерии приёмки

- AC-01: при активной ссылке шаблон содержит `tg://resolve` с username и тем же start-параметром, что HTTPS fallback.
- AC-02: fallback остаётся кликабельной ссылкой `https://t.me/...` и оба варианта не раскрывают токен за пределами пользовательской страницы.
- AC-03: привязка по-прежнему требует подтверждения в Telegram и исходной браузерной сессии.

## Решение и влияние

Telegram описывает схемы `t.me/<bot>?start=<parameter>` и `tg://resolve?domain=<bot>&start=<parameter>` для запуска бота. Основной переход будет прямым приложенческим URL, HTTPS ссылка — fallback для браузеров без зарегистрированного tg:// handler. Публичный `/hope/` page уже отдаётся через Caddy; production обновляется обычным code deploy.

Источник: [Telegram Deep Links](https://core.telegram.org/api/links).

## Итог и ограничения

Фактическое handoff на конкретном устройстве остаётся непроверенным. Пользователь может открыть страницу привязки, нажать основную кнопку и сообщить, запустился ли Telegram; HTTPS fallback остаётся рядом. Для проверки полного flow нужен собственный аккаунт и действующая пользовательская сессия; искусственные сообщения в production не отправлять.
