# 0024 — Автоматический импорт панели после входа администратора

Статус: verified (CI PostgreSQL + Czech deploy; реальный пользовательский сценарий не проверен). Создано: 2026-10-13. Обновлено: 2026-10-13.
Связанные требования: R-02, R-04, R-08. Решения: не требуются.

## Проблема и результат

После входа приходится вручную нажимать «Импортировать из панели». Выполнять
тот же импорт один раз после успешного административного входа.

## Объём и требования

- Новый парольный вход активного staff-пользователя отмечает ожидающий импорт.
  Он выполняется после успешного MFA, включая настройку TOTP и доверенный браузер.
- До проверки второго фактора импорт не выполняется. Клиентский вход его не запускает.
- Навигация, обновление страниц и повторная MFA в той же сессии не запускают
  новый импорт. Новый парольный вход запускает новую попытку.
- Используется `import_clients`: чтение панели, прежние защиты идентичности,
  исключений и конфликтов, аудит и итоговое уведомление админской группы.
- При ошибке панели вход сохраняется, пользователь видит сообщение. Автоматическая
  попытка не повторяется до следующего входа; ручная кнопка позволяет повторить.
- Первоначально код и документы подготовлены без выкладки, обращения к реальной панели и
  изменения локальных работающих баз/сервисов. Тесты — отдельная SQLite в памяти,
  имитация импорта, Telegram API не вызывается.

## Критерии приёмки

- AC-01: пароль без успешного MFA не вызывает импорт; после правильного MFA
  выполняется ровно один импорт, последующая навигация его не повторяет.
- AC-02: валидный доверенный браузер запускает импорт после правильного пароля;
  неверный пароль или недействительная cookie не дают обхода MFA.
- AC-03: новый вход запускает новую попытку; клиентский вход не запускает импорт.
- AC-04: ошибка панели не отменяет вход и не создаёт автоматические повторы;
  ручная кнопка остаётся рабочей.
- AC-05: настройка TOTP завершает ожидающий импорт; повторная MFA без нового
  парольного входа не запускает импорт.

## Решение и влияние

Маркер `staff_import_pending` устанавливается в `bound_login` только для staff.
Парольный вход с доверенной cookie завершает MFA и импорт в login POST; прочие
входы — в успешном MFA POST. Внешнее чтение выполняется после транзакции MFA.
GET страниц не запускают импорт. Общий обработчик импорта сохраняет ручной POST
и одинаковую обработку ошибок. Миграция для этого изменения не нужна.
Импорт синхронный: время входа увеличивается на чтение панели, как при ручном
нажатии. Настройки HTTP timeout и существующая семантика частичного импорта сохраняются.
