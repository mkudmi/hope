# 0026 — Главное меню кабинета после завершения привязки Telegram

Статус: verified (изолированные тесты; не развёрнуто). Создано: 2026-10-13. Обновлено: 2026-10-13.
Связанные требования: R-01, R-03, R-08. Решения: не требуются.

## Проблема и результат

После окончательной привязки Telegram пользователь получает только подпись об
успехе. Вместо этого бот должен показать главное меню связанного аккаунта без
дополнительного `/start`.

## Объём и требования

- Только после подтверждения обеих сторон и создания TelegramIdentity в исходном
  браузере ставить одно персональное уведомление с главным меню аккаунта.
- Использовать общую клавиатуру `menu()`: подписка, подключение VPN, продление,
  тарифы, заказы, помощь и HTTPS ссылка на кабинет по текущим настройкам.
- Предварительная кнопка «Это мой аккаунт» по-прежнему просит вернуться в
  браузер; до окончательной привязки кабинет в боте не открывается.
- Уведомление остаётся в транзакционном outbox с прежним уникальным ключом.
  Повторная доставка и подтверждение не создают отдельный `/start`/дубль события.
- Worker формирует клавиатуру из общего меню. Только личная активная TelegramIdentity
  получает её: при отвязке до отправки уведомление не перенаправляется группе.
- Кнопки работают с текущим связанным аккаунтом через обычную проверку Telegram ID.
  Привязка не меняет VPN-параметры и не объявляет рабочий туннель.
- Подготовить код и документы без выкладки и изменения работающих баз/служб.
  Тесты изолированы, Telegram API имитируется.

## Критерии приёмки

- AC-01: до финального web-подтверждения нет уведомления с кабинетом; после
  него одно уведомление содержит общий linked-menu и идёт в личный чат.
- AC-02: «Моя подписка» из новой клавиатуры показывает подписку именно этого
  аккаунта; VPN-снимок и версия не изменяются.
- AC-03: повторное подтверждение отклоняется без нового уведомления; retry
  использует тот же outbox элемент и полноценную клавиатуру.
- AC-04: при отвязке до доставки меню не отправляется и не попадает в группу;
  обычные персональные и административные уведомления не получают эту клавиатуру.
- AC-05: меню совпадает с общей клавиатурой связанного аккаунта, HTTPS URL
  соблюдает SITE_URL и /hope/; подтверждение кандидата не получает меню.

## Решение и влияние

Добавить `Notice.telegram_account_menu` (Boolean, default=False), миграция 0009.
`confirm_web` создаёт обычное персональное сообщение с этим флагом. `deliver_notices`
проверяет наличие личной identity и добавляет сериализованную общую клавиатуру
из `core.bot.menu`. Рендеринг выполняется worker, поэтому сетевого вызова из web
или транзакции привязки нет. Новые настройки не требуются.

## Итог и ограничения

Код, миграция и документация подготовлены. Рабочий Telegram клиент и доставка
на стенде не проверены; выкладка отложена. Работающие базы/сервисы и VPN-панель
не затрагивались. Проверка PostgreSQL concurrency пропущена в SQLite; новые
правила привязки не меняют прежние блокировки/уникальность.
