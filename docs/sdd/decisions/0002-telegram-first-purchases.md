# 0002 — Заказы в Telegram до браузерного аккаунта

Дата: 2026-10-12. Статус: accepted.
Требования: R-03, R-05, R-15. Изменение: [0004](../changes/0004-complete-bot.md).

## Контекст

Полный сценарий покупки не должен требовать предварительной регистрации в браузере. Оплату владелец проверяет вручную; старые пользователи панели не должны терять проверку владения.

## Решение

BotContact идентифицирует личный Telegram-чат, PurchaseOrder сохраняет выбранные цену/срок и отдельное состояние ручной оплаты. До выдачи заказа HOPE-аккаунт не требуется. Только после ручного подтверждения перевода и отдельного подтверждения выдачи создаются новый аккаунт с unusable password, новая подписка и TelegramIdentity. Для известной связанной подписки выполняется продление с проверкой текущей привязки/версии. Старые несвязанные записи панели через покупку не присваиваются.

В новый Telegram-аккаунт браузерный вход добавляется одноразовой ссылкой из личного бота: 15 минут, новый логин/пароль, восемь кодов восстановления. Ссылка — секрет, как recovery-link; пересылать её нельзя. Уже настроенный аккаунт использует обычный вход/восстановление. Старые аккаунты сохраняют двустороннюю привязку из исходного браузера.

Уведомления о заказе/ответы поддержки адресуются BotContact через существующий outbox даже без User. Прямой адресат и User взаимоисключены DB constraint. Эти сообщения не являются общей рассылкой подписчиков; секрет подписки выдаётся только по действующей TelegramIdentity в личном чате.

## Последствия и альтернативы

Нужны миграция своей базы и тесты восстановления новых связей. Статус paid не означает готовый VPN; fulfilled устанавливается после verified операции. Callback IDs проверяются по владельцу, активный заказ один, действия сериализуются PostgreSQL.

Обязательная регистрация в браузере до выбора тарифа отклонена запросом полноценного бота. Внешняя платёжная интеграция/автопроверка перевода исключены условиями владельца. Хранение заказов в памяти/FSM не обеспечивает восстановление после перезапуска.
