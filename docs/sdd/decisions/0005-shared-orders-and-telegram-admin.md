# ADR 0005 — Общие заказы web/Telegram и доверенные Telegram администраторы

Дата: 2026-10-13. Статус: accepted. Изменение: [0027](../changes/0027-web-renewal-and-telegram-admin.md).

## Контекст

Веб-продление нужно обслуживать из чата, сохраняя необязательность Telegram для
клиента и штатную защиту операций панели. Владелец разрешил административные
действия своему ID и доверенным ID из окружения.

## Решение

Расширить PurchaseOrder вместо параллельного платёжного workflow. Для web заказ
принадлежит User/Subscription; contact необязателен. Ручные ответы хранятся в
OrderMessage, администраторам их не зеркалировать. Telegram административная
авторизация использует числовой allowlist и конкретный чат; staff actor берётся
из ADMIN_TELEGRAM_LOGIN, исходный Telegram ID сохраняется в аудите/причине.
Веб сохраняет TOTP/CSRF. Подтверждение нового канала требует отдельного
краткоживущего предпросмотра и создаёт ту же Operation с UUID заказа.

## Последствия и альтернативы

Оба интерфейса видят общую историю/статус; потребуются штатная миграция и явная
настройка trusted IDs при будущей выкладке. Изменения состава группы не дают
права на продление. Раздельные модели web request и bot order усложнили бы
идемпотентность; доступ всем администраторам группы отвергнут пользователем.
Telegram administrator identity отделена от клиентской TelegramIdentity.
