# ADR 0004 — Постоянный production runtime в Чехии

Дата: 2026-10-13. Статус: accepted. Связано: [SDD 0017](../changes/0017-czech-production.md).

## Контекст

Первичная раскатка запускала только web, оставляла bot/worker остановленными и
держала `PANEL_WRITES_ENABLED=false`. Владелец прямо разрешил production-режим,
ручные реальные операции через приложение и постоянную работу bot/worker.

## Решение

- На Czech deployment явно включить real panel и writes; в локальном окружении
  сохранить write-off.
- Использовать ручной workflow_dispatch для production rollout.
- Перед стартом worker проверять, что очередь операций не содержит queued или
  applying; не запускать отложенные записи автоматически при cutover.
- Оставить единственную точку записи в панели через имеющиеся административные
  действия с предпросмотром, ручным подтверждением, аудитом и сверкой.
- Не менять клиентов ради диагностики; deploy не создаёт операций/уведомлений.

## Последствия

Приложение принимает реальные обращения и обрабатывает только подтверждённые
владельцем действия; ошибки API/Telegram требуют наблюдения после запуска.
Worker может доставлять настоящие outbox-сообщения, появившиеся в production.
Панельные вызовы могут менять только объект конкретной подтверждённой операции.
Публичный `/hope/` и создание владельца остаются отдельными задачами.

## Альтернативы

- Оставить standby — не соответствует прямому требованию владельца.
- Разрешить записи, но держать worker выключенным — операции накапливаются и
  product flow не завершается.
- Перезапустить/редактировать 3x-ui напрямую — вне интеграционного контракта и
  не требуется для запуска HOPE.
