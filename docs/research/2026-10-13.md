## Telegram диплинк для привязки — SDD 0020

Production BOT_USERNAME и Telegram `getMe` совпали: `hope2vpnbot`; HTTPS профиль
бота на `t.me` отвечает 200. Пользователь сообщил, что переход из webview не
открывает Telegram app. Согласно [официальному формату Telegram](https://core.telegram.org/api/links),
для bot start поддерживаются как `https://t.me/<bot>?start=<parameter>`, так и
`tg://resolve?domain=<bot>&start=<parameter>`. Реализация добавляет прямую
схему приложения и сохраняет HTTPS fallback с тем же краткоживущим токеном.
Commit `4bfc4a4` прошёл production workflow [run 38399164581](https://github.com/mkudmi/hope/actions/runs/38399164581): ruff, Django check, collectstatic, pytest и migration check успешны. Web получил шаблон с `tg://resolve` + HTTPS fallback; `/hope/login/` отвечает 200, `/hope/staff/` требует вход (302), web healthy, bot/worker работают. На пользовательском устройстве диплинк ещё не проверен; сообщения боту не отправлялись.

## Восстановить уведомление о существующей подписке

Пользователь сообщил, что после кнопки «У меня уже есть подписка» группа не
получает событие. На сервере Чехии read-only проверка обнаружила открытую
binding-заявку без Notice. Заявка была создана в 12:26 UTC, production staff
пользователь появился в 12:32 UTC. `admin_event()` находит получателя через
активную staff-запись и при её отсутствии возвращает `None`, поэтому уведомление
тогда не было создано. Это объясняет инцидент; отсутствие сообщения не было
ошибкой доступа к группе.

Бот является администратором группы; read-only Telegram API вернул успешный
`getMe` и статус `administrator` для `getChatMember`. Для существующей открытой
заявки создано ровно одно пропущенное admin-event в outbox. Worker доставил его:
Notice получил `sent` за одну попытку. Повторная заявка не создавалась. Локальные
контейнеры и база не изменялись; панель 3x-ui и её клиенты не затрагивались.
