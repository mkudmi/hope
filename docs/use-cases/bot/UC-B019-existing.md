# UC-B019 — Существующая подписка и ожидание

Дата сверки: 2026-10-12. Статус: описана текущая реализация.

## Участник и триггер

**Участник:** Пользователь Telegram.  
**Кнопка / действие:** У меня уже есть подписка; Существующая подписка; Проверить привязку; existing.

## Предусловия

Личный чат; пользователь ещё не связан с активным аккаунтом.

Действия с аккаунтом выполняются в личном чате; callback ограничены по частоте. Сбой Telegram-доставки не отменяет сохранённую заявку/заказ.

## Основной сценарий

1. Нажать кнопку.
2. Сервис блокирует контакт и возвращает открытое binding-обращение либо создаёт одно.
3. В группу ставится уведомление с username, именем/фамилией при наличии, ID и контактом.
4. Бот показывает ожидание без просьбы написать текст.
5. Администратор проверяет прежний контакт, находит запись и лично выдаёт приглашение.

## Результат и побочные эффекты

Одна открытая заявка; автоматической привязки нет.

Request и административный Notice создаются транзакционно; отсутствие username/фамилии допустимо. Имя не доказывает владение.

## Альтернативы и ошибки

Повторные/конкурентные нажатия не создают дубль. Уже связанный активный аккаунт: сообщение о готовой привязке. После закрытия допускается новая заявка. Входящий текст во время ожидания не создаёт новое обращение без отдельного режима поддержки.

## Критерии приёмки

- С правильными предусловиями нажатие приводит к описанному результату.
- Альтернативы и отказ не приводят к неописанной смене срока, владельца или Telegram-привязки.
- Проверить основной сценарий и перечисленные ошибки на тестовых данных; персональные секреты не включать в отчёты.

Критерии выше — план проверки этого UC. В данной задаче сверяется документация; новый прогон продуктовых тестов по каждому UC не заявляется. Связанные существующие проверки: [карта требований SDD](../../sdd/SPEC.md).
